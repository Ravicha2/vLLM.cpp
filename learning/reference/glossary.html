Glossary

The words this project uses, and what they mean here. Every lesson sticks to these terms. Phase tag shows where the term first earns its keep.

The basics

Token phase 1
A chunk of text (roughly a word-piece) that the model reads and writes. Models generate one token at a time.
Logits phase 1
The raw, unbounded scores the model gives every token in its vocabulary before turning them into probabilities. Bigger score = more likely.
Softmax phase 1
Turns a list of logits into probabilities that sum to 1. Written stably by subtracting the maximum logit first, so large scores don't overflow. See Lesson 1.
Tensor phase 1
A multi-dimensional array of numbers. Here it's a thin wrapper over Eigen, not a new tensor library.
matmul phase 1
Matrix multiplication. The bulk of the arithmetic in a transformer.
Float32 / FLT_MAX / overflow / NaN phase 1
32-bit floating point. Its largest finite value is about 3.4e38; a calculation that goes past that produces inf ("overflow"), and inf/inf produces NaN ("not a number") — a silently wrong value, not an error.
Log-sum-exp phase 1
The identity log Σ ex = m + log Σ ex−m with m the max. The robust way to compute softmax, or its logarithm.

Attention

Attention phase 1
The step where each token gathers information from earlier tokens, weighted by how relevant they are. Each token produces a query (what it's looking for), and every token has a key (what it offers) and a value (what it passes on).
Head / multi-head attention phase 1
Attention run several times in parallel with different learned weights ("heads"), so the model can attend to different things at once. Their outputs are concatenated.
Grouped-query attention (GQA) phase 1+
A cheaper variant where several query heads share one set of key/value heads. Start without it; add once multi-head works.
Causal mask phase 1
A rule that stops a token attending to tokens after it. Required so generation can't peek at the future. In incremental decode it happens for free; in a full recompute you must apply it explicitly.
RMSNorm phase 1
A cheap normalisation applied before attention and before the MLP. Scales each vector by its root-mean-square size, no mean subtraction.
RoPE phase 1
"Rotary position embedding." Encodes a token's position by rotating its query and key vectors by an angle that depends on absolute position. The classic source of off-by-one, silently-wrong answers.
SiLU / SwiGLU phase 1
The activation function inside the MLP. SiLU is x · sigmoid(x); SwiGLU uses it to gate one branch with another.
Residual connection phase 1
Adding a layer's input back to its output. Lets information skip past a layer and makes deep stacks trainable.

The cache

KV cache phase 1
Stored key and value vectors for tokens already processed, so each new token doesn't recompute them. The reason generation is not quadratic in the number of tokens.
Prefill vs decode phase 1
Prefill processes the prompt all at once; decode produces the answer one token at a time, reading the cache. Phase 1's test is that the two agree.
PagedAttention phase 2
vLLM's core idea: split the KV cache into fixed-size blocks instead of one contiguous buffer per sequence, so memory can be shared and reused.
Block / block table phase 2
A block holds a fixed number of tokens' K/V (16 here). A sequence's block table lists which blocks are its own, in order.
Block pool / free list phase 2
The shared supply of blocks, plus the queue that decides which free block to hand out next (least-recently-used first).
Copy-on-write phase 2
When two sequences share a block and one needs to change it, that sequence copies the block first so the other isn't disturbed. How prefix sharing stays safe.
Prefix caching phase 5
Reusing KV blocks for prompts that share a common start, by matching block hashes.

Running the engine

Continuous batching phase 3
Adding and removing requests between decode steps, instead of waiting for a whole batch to finish. Keeps the engine busy; the main source of vLLM's throughput.
Scheduler phase 3
Decides, each step, which requests to run and how many tokens they may use, given memory and token budgets.
Greedy sampling phase 1
Always pick the highest-probability token. Deterministic.
Temperature phase 1
Divides the logits before softmax. Lower = more predictable, higher = more random. Temperature 0 means greedy.
Top-p (nucleus) sampling phase 1
Keep the smallest set of most-likely tokens whose probabilities add up past p, discard the rest, renormalise, then sample.
Epsilon (float epsilon) phase 1
A tiny tolerance for "close enough" when comparing two float results. Phase 2's proof that paged equals naive is "equal within epsilon."
