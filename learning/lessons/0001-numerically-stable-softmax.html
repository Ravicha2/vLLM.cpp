The softmax that doesn't explode

One small function sits at the centre of every attention layer. Written the obvious way it returns NaN on exactly the inputs a real model produces — and nothing throws. You'll write the version that doesn't, and prove it with a test.

Your win by the end A vllmcpp::softmax in include/vllmcpp/ops.h and a passing tests/test_ops.cpp, wired into ctest.

Why this, and why now

Attention decides what each token looks at by producing a set of scores, one per previous token, and turning them into weights that sum to 1. That normalisation step is softmax. It runs once per attention head, per layer, per token — so it is the first real kernel your engine needs, and it is where the project's whole theme starts: code that produces a plausible-looking wrong number instead of an error.

Phase 1's promise is that a cache-grown decode must match a fresh recompute. That guarantee is only meaningful once the pieces underneath it are numerically correct. This lesson gets the first piece right. It is one slice of issue #1; matmul and the tensor wrapper come alongside it.

The idea, in one line

Softmax takes a list of raw scores (called logits) and turns them into a probability distribution:

softmax(z)i = ezi ⁄ Σj ezj

Bigger logit → bigger probability, and the whole list sums to 1. Simple.

The bug hiding in the obvious version

Write it exactly as the formula says and feed it what a model actually emits. Logits are unbounded — a confident model can produce a score of 900, or 10 000.

// The naive version — correct on paper, broken on a real machine.
std::vector<float> softmax(const std::vector<float>& z) {
  float sum = 0.f;
  std::vector<float> out(z.size());
  for (size_t i = 0; i < z.size(); ++i) { out[i] = std::exp(z[i]); sum += out[i]; }
  for (float& x : out) x /= sum;
  return out;
}

In 32-bit float the largest finite number is about 3.4e38, and ex sails past it once x is roughly 88.7. Beyond that, exp returns inf — documented, not an accident.

881.65e38
89inf ← already over the edge
1000inf

Now the denominator is inf, every numerator is inf, and inf / inf is NaN. No exception, no warning: your attention weights quietly become NaN, which spreads through the layer and turns the output to mush. This is the same class of failure Phase 2's "paged must equal naive" test exists to catch, just one level down.

The tell If your test feeds {1000, 1001, 999} and the probabilities come back as nan, nan, nan — or the sum isn't 1 — you have this bug, not a test bug.

The fix: subtract the max

Softmax doesn't care about the absolute size of the logits, only their differences. Shifting every logit by the same amount c leaves the result unchanged — the factors of ec cancel top and bottom:

ezi−c ⁄ Σj ezj−c = ezi ⁄ Σj ezj

So pick c = the largest logit. Now the biggest exponent is e0 = 1 and every other one is ≤ 1. Nothing overflows, ever — no matter how large the raw logits were. This is the same move as the log-sum-exp trick, which you'll meet again whenever you need log(softmax) (a loss function, say) rather than the probabilities themselves.

Your task

  1. Add the header. Create include/vllmcpp/ops.h with a softmax that takes a span of logits and returns a std::vector<float> of probabilities. Subtracting the max is the whole assignment — keep it small. 
    #pragma once
#include <span>
#include <vector>

namespace vllmcpp {
std::vector<float> softmax(std::span<const float> logits);
}
  2. Write the test. Create tests/test_ops.cpp. Use CHECK from tests/check.h (not assert — it's compiled out in Release). Cover three things: a normal case, the overflow case, and the edge of an empty list. 
    #include <cmath>
#include <span>
#include <vector>

#include "vllmcpp/ops.h"
#include "check.h"

int main() {
  // 1. Normal case: largest logit gets the largest probability, sums to 1.
  std::vector<float> z{1.f, 2.f, 3.f};
  auto p = vllmcpp::softmax(std::span<const float>(z));
  float sum = 0.f; for (float x : p) sum += x;
  CHECK(std::abs(sum - 1.f) < 1e-5f);
  CHECK(p[2] > p[1] && p[1] > p[0]);

  // 2. The overflow case. Naive exp() would give inf/inf = NaN here.
  std::vector<float> big{1000.f, 1001.f, 999.f};
  auto q = vllmcpp::softmax(std::span<const float>(big));
  float qsum = 0.f; for (float x : q) qsum += x;
  CHECK(std::isfinite(qsum));          // no NaN, no inf
  CHECK(std::abs(qsum - 1.f) < 1e-5f);
  CHECK(q[1] > q[0] && q[0] > q[2]);    // order preserved

  return 0;
}
  3. Wire it in. In CMakeLists.txt add the source to the library and register the test with the existing helper: 
    vllm_add_test(test_ops)
  4. Run it. cmake --build build && ctest --test-dir build --output-on-failure — it should pass on the first honest attempt. Then, to feel the bug, change the test to call your old naive version and watch it go nan.
Reference solution (try it first — then compare) 
std::vector<float> softmax(std::span<const float> logits) {
  std::vector<float> out(logits.begin(), logits.end());
  if (out.empty()) return out;

  const float max_z = *std::max_element(out.begin(), out.end());
  float sum = 0.f;
  for (float& x : out) { x = std::exp(x - max_z); sum += x; }
  for (float& x : out) x /= sum;
  return out;
}

One subtlety worth noticing: sum can never be 0 here, because the max element contributes exactly e0 = 1. That's a free guardrail of the max-subtraction — hold onto it.
